## Executive Summary
This target exposed an MCP server where one tool (`run_model_evaluation`) accepted unsanitized user input in `benchmark`. That input reached a shell execution path, enabling command injection and host proof extraction.

## Attack Chain

2. Enumerate available MCP tools
3. Test tool trust boundaries
4. Confirm command injection in `benchmark`
5. Read `/root/proof.txt`

## Step 4 — Boundary Testing
### 4.1 URL fetch tool
`fetch_knowledge_source` blocked private/internal SSRF targets.

### 4.2 Evaluation tool
`run_model_evaluation` looked risky because it accepts freeform string fields.

### Injection probe
```bash
mcporter call http://127.0.0.1:19090/mcp.run_model_evaluation --allow-http \
  model_name=smollm2 \
  'benchmark=mmlu;id' \
  subset=all \
  num_samples=1 \
  --output json
```

## Root Cause
`benchmark` was handled unsafely and reached shell execution context without strict validation/escaping.

Likely anti-patterns:
- shell command string concatenation
- no allowlist for benchmark values
- no metacharacter filtering

---

## Security Recommendations
1. Remove shell execution for user-controlled parameters
2. Use argument-array subprocess calls (no shell)
3. Allowlist `benchmark` values
4. Run service as non-root
5. Apply runtime hardening (seccomp/apparmor/egress controls)
6. Add explicit payload validation and monitoring
